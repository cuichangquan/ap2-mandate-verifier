## Why a green SDK/schema result is not the security oracle

Selective-disclosure decoys appear as issuer-signed digest commitments even though there is no actual Disclosure the holder can reveal for them. The Root signature makes the digest authentic but does **not** tell the Merchant whether its hidden preimage is a decoy or an undisclosed authorization-bearing claim. The candidate's immutable fixed-Issuer policy therefore rejects unknown `_sd` regardless of what the official SDK's resolved Open and JSON Schema show.

The DC04 signed-decoy negative was a useful candidate regression, but did not explicitly report the exact **unresolved signed digest positions**, full schema for that variant or a separate DC05 acceptance gate. We do not count that earlier result as DC05.

Record actual location, not an assumed root-only position; if no such digest is created, BLOCKED/HOLD.

The rejection's `unsupported_profile` classification is derived from a bounded, observable Ruby code location and supported by O1–O3. Do not claim the Ruby code identified a decoy by examining its digest.
