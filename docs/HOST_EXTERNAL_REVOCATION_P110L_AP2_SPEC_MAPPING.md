## 5. Merchant向けRubyライブラリへの具体的な示唆（実装承認ではない）

- **標準に沿った狭い責務（将来候補）:** 固定されたIssuer信頼設定、SD-JWT VC/委任チェーン検証、`vct`の厳密照合、`aud`/`nonce`、open→closed constraints、Checkout JWTとhash/最新Checkout照合、未知重要constraintのFail Closed、責務を示す構造化された**検証証拠**の返却。署名・nonce freshnessやHost契約の最終判断は境界ごとに明確化する。これはP0/P1で既に検討したVerifier研究の焦点と一致する。
- **Merchant Host / 個別Authorityが別途負う責務:** 購入の最終ALLOW、Host nonce一意性/operation・outbox、強いreplay防止、外部失効`R_effective < C`の直列化、独立Authority proof認証・耐久中止・復旧・顧客への表示、実決済/返金/Receiptの生成。これらをVerifierの`verified: true`という返り値に内包しない。
- **設計の分岐:** もしGemがあくまで「署名・Mandate・Checkoutの静的暗号検証」を提供するなら、HC06の強い外部失効機能を**実装済み/標準準拠機能として同梱したように表現しない**。強い即時失効の保証が製品要件なら、C01〜C12未達の間はプロダクション統合不可。Gem公開やPoCへのGO判定は**今回行っていない**。
