# AP2 Ruby Gemの目指す姿

状態：将来ビジョン。実装計画・機能やGemの公開承認・納期の約束ではありません。
読解基準main：`c4b25e11ad2910d7be3e961bff36dfcc315b1d55`。

## Ruby開発者に届けたい価値

**Ruby開発者が、AP2の複雑な署名・委任ルールを自作せず、安全に扱えるGemを目指します。**
安全性を主張だけで成立させず、対応仕様・信頼の前提・独立した検証証拠・未対応事項を利用者が確認できる形で提供します。
固定profileは初期の足場であり、最終目的ではありません。最初は検証専用Gemでよく、そのコアを堅実に完成させてから、最終的にAP2 Ruby SDKへ広げる方向を目指します。

## 大切にする設計方針

1. **AP2規格に忠実で、対応範囲が明確。** 対象の仕様版・profile・署名形式・委任形状・制約を明示します。規格由来の要件とGem独自の厳格化を区別し、対応範囲を証拠とともに段階的に広げます。未対応の正規AP2データを、規格違反と決めつけません。
2. **安全な検証コア。** 署名、委任と鍵の結合、署名対象原文と開示の完全性、購入内容binding、期限、Schemaと対応制約を検査します。署名だけ・可視部分だけの成立を成功へ昇格せず、不明・未知・未対応を推測で許可しません。
3. **Rubyから理解して使える。** 明確なAPIと入力契約、失敗理由とエラー対応、導入例・使用例、対応Ruby/依存/provider、版更新時の互換性方針を整えます。架空のAPIを実装済みとして案内せず、検証失敗と処理系障害を区別します。
4. **Rails非依存のコア。** Ruby単体で利用できる検証コアを保ちます。必要なら将来、Rails向けの別Gemでアプリ連携を補助する余地を残します。別Gemの作成や構成は未決定です。

## GemとHostの責任分担

| Gemの責任 | 利用側Hostの責任 |
| --- | --- |
| 既存の厳格入力上限、登録/選択/profileの整合、署名・委任・原文/開示閉包、Schema/制約、購入/Host binding、供給時刻での期限交差を検査 | 信頼する発行主体・用途・鍵の真正な出所を決定し、最新の失効・登録状態、信頼時計、現在注文/challengeを供給 |
| 対応範囲の検査事実をEvidenceとして返し、不正入力や判断不能を成功にしない | Evidenceの使用直前にも最新状態を照合し、nonceの原子消費と注文CAS、結果不明時の照会/再試行境界、最終業務判断・決済を担当 |

**EvidenceはALLOWでも購入許可でも決済完了でもありません。** Gemは外部の信頼元や失効情報の最新性を独立証明しません。任意の公開鍵の登録だけでは信頼は成立せず、Hostが信頼根拠や最新状態を確認できなければHOLDです。
Gem自身が実装済みの検査をHostへ移して省略する方針ではありません。現行Evidenceは信頼する同一Rubyプロセス内の不変な検査事実であり、JSON化したHashから真正性を復元するAPIではありません。
